# Kala-MeetingMinutes 设计

## 目标

创建全局 Skill `kala-meeting-minutes`，把录音转录文本稳定转换为内容可追溯、范围准确、视觉可读、能安全发布到飞书的会议纪要。Skill 以 `kala-feishu` 作为飞书读写与原生画板能力层；没有飞书能力时生成可审阅、可延后发布的本地纪要包。

## 已验证的用户需求

- 从录音转录文本提炼会议总结、关键结论、待办、智能章节、金句及完整转录附录。
- 参考飞书妙记样例的提炼方式、信息密度、文档层级和视觉表现，而非只模仿栏目名称。
- 重要结论必须保留原文中的逻辑关系。例如“LLM 决定做什么和行动目标，GOAP 围绕目标规划执行路径”不能被泛化掉。
- 用户给定的时间范围、说话人映射、专有名词与角色命名优先于模型推断。
- 图中的箭头、反馈回路、层级与相对位置也是信息，不能只保留文字块。
- 发布前明确目标飞书账号、目录、文档与替换位置；用户要求替换原始白板位置时，不能追加到文末。
- 有飞书能力时直接发布并回读验证；没有飞书能力时生成本地待发布包。

## 方案比较

### 方案 A：纯提示词 Skill

全部规则放进 `SKILL.md`。实现快，但上下文过长，内容核验、位置替换、跨设备部署和视觉验收仍依赖临场发挥，无法满足“稳定”要求。

### 方案 B：分层编排型 Skill（采用）

`SKILL.md` 只保留主流程和路由；参考文件承载提炼方法、飞书版式规范、质量标准与降级策略；模板固定交付结构；Node 脚本执行本地包的确定性验证。飞书发布复用 `kala-feishu`，不重复实现 OAuth、云文档、图片和画板 API。

### 方案 C：完整自动化程序

自行实现转录解析、摘要、图形渲染和飞书发布。自动化程度高，但会重复 `kala-feishu`，同时把本应由 LLM 判断的语义提炼固化成脆弱代码，维护成本过高。

## 总体架构

```text
录音转录 / 样例纪要 / 白板素材 / 用户约束
                     │
                     ▼
              证据账本与范围锁定
                     │
                     ▼
          内容提炼 ──→ 视觉与位置规划
                     │
                     ▼
              内容 QA + 视觉 QA
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
  kala-feishu 可用        kala-feishu 不可用
  精确发布与回读          生成本地待发布纪要包
```

Skill 不把“生成内容”和“写入飞书”混成一个不可检查的步骤。纪要内容先形成证据可追溯的中间产物，通过质量门后才进入发布层。

## 工作流

### 1. 输入与能力预检

收集并确认：转录文本或可访问链接、样例纪要、目标会议范围、说话人映射、术语映射、白板或图片素材、目标飞书文档/目录/账号。只有链接且无法读取原文时停止，要求用户导出或粘贴文本。

### 2. 反推样例方法

若用户提供样例纪要和对应完整转录，先比较“原文说了什么”和“样例保留了什么”，识别其栏目顺序、信息压缩比例、决策表达、待办格式、章节粒度、金句选择、完整转录保留方式及视觉组件。样例中的事实不能混入新会议。

### 3. 建立证据账本

按时间段记录议题、说话人、事实、观点、已确认结论、倾向方案、待办、开放问题、后续范围和证据时间戳。关键结论与待办必须能回指原文；缺失负责人或日期时明确标为未确认。

### 4. 锁定范围与主线

用会议目标和用户补充约束确定纪要主线。将未来阶段、旁支讨论和未定方案放入“开放问题”或省略，不能挤占当前重点。例如用户指定聚焦 8 月时，不展开尚未确定的 9 月细节。

### 5. 生成纪要内容

按“总结 → 关键结论 → 待办 → 智能章节 → 关键决策/金句 → 相关资料 → 完整转录”的阅读层级生成。表达必须区分：讨论过、倾向、已确认、尚未决定。模糊或内部黑话改写成协作者可理解的准确表述，同时保留含义。

### 6. 视觉与位置规划

根据关系复杂度选择普通文档块、飞书原生画板、SVG/PNG 或原始图片。视觉媒介一旦由用户确认，不擅自互换。发布计划记录目标块、插入索引、替换/追加语义、资产类型、尺寸和需要保留的关系。关系图必须保留箭头、反馈回路和方向。

### 7. 双重质量门

内容 QA 检查证据、完整性、范围、人员、日期、术语、结论层级和待办可执行性。视觉 QA 检查字体、超框、间距、箭头、比例、阅读顺序、样例一致性和实际渲染。任一门不通过都不能发布。

### 8. 飞书发布与验收

有 `kala-feishu` 时先读取目标文档块树和路由账号，列出会删除或替换的块并取得确认，再执行精确写入。发布后回读块顺序、图片尺寸、画板节点、重复标题、旧素材残留，并查看实际渲染。结构正确但位置错误或视觉不可读均不算完成。

### 9. 无飞书能力的降级

在当前项目的 `.meeting-minutes/<YYYY-MM-DD>-<会议主题>/` 生成待发布包；不在项目中时使用 `~/Documents/Kala/MeetingMinutes/`。包内包含：

- `meeting-minutes.md`：纪要正文；
- `source-map.json`：结论与原文证据映射；
- `preview.html`：最终阅读顺序和视觉预览；
- `visuals/`：SVG、PNG、原图及画板布局规格；
- `publish-plan.json`：未来飞书写入的精确位置与操作；
- `qa-report.md`：内容、视觉、权限和未确认项检查结果。

待发布包不写进 Skill 安装目录，也不默认提交 Git。以后在有 `kala-feishu` 的设备上直接发布该包，不重新总结。

`SKILL.md` 控制在 500 行以内。参考文件按任务阶段渐进读取；验证脚本使用 Node.js 18+ 标准库，不增加 npm 依赖。保留 `scripts/` 也使 Cursor 按本机惯例把它安装为真正的 Skill 目录，而非单文件命令。

## 质量标准

### 内容质量

- 所有关键结论与待办均有原文时间戳或明确证据说明；
- 不把讨论、猜测或候选方案写成已确认结论；
- 用户指定的范围、人员映射和术语全部生效；
- 会议主线、关键架构结论和明确待办不能遗漏；
- 日期、负责人、依赖和开放问题缺失时显式标注；
- 完整转录按模板要求保留，不用摘要替代原始证据。

### 排版与视觉质量

- 栏目层级、信息密度和视觉组件与所选样例一致；
- 画板正文达到可读字号，不超框、不挤压，卡片留白均衡；
- 关系图保留方向、箭头、回路和层级；
- 原生画板、SVG 和原始图片按用户确认的媒介呈现；
- 替换发生在目标原块位置，不产生文末重复内容；
- 发布后以真实块树和实际渲染为验收证据。

## 测试设计

1. 完整飞书场景：输入转录、两份样例、说话人映射、月份范围和两类视觉素材，验证内容提炼、原生画板 + SVG 混合呈现、原位置替换与发布后回读。
2. 无飞书场景：只提供本地转录和素材，验证待发布包完整、路径正确、预览可打开、发布计划可供另一台设备继续。
3. 证据不足场景：只提供不可访问链接或存在歧义的白板，验证 Skill 停止猜测、列出缺失证据和最小问题。
4. 本地确定性测试：验证包结构、JSON 格式、必需章节、资源引用、相对路径和禁止状态词。
5. 部署测试：验证 Windows 安装预览、选择性安装、三端目标目录、manifest/index 更新；验证 macOS/Linux 薄封装仍调用同一 `install.mjs`。

## 部署设计

- 源目录：`Kala-Skill-Kit/skills/kala-meeting-minutes/`；
- Codex：遵循本机可复用 Skill 规范安装到 `~/.agents/skills/kala-meeting-minutes/`；
- Claude Code：安装到 `${CLAUDE_CONFIG_DIR:-~/.claude}/skills/kala-meeting-minutes/`；
- Cursor：因包含 `scripts/`，安装到 `~/.cursor/skills/kala-meeting-minutes/`；
- 更新三端 `_manifest.json` 和 `_index.md`；
- 将名称加入 `install.mjs` 的 `SKILLS` 数组，并更新 README；
- 安装器先执行 `--dry-run --tools codex,claude,cursor kala-meeting-minutes`，用户确认预览后再真实安装。

当前安装器仍把 Codex 指向 `~/.codex/skills`，与本机真实管理目录 `~/.agents/skills` 不一致。实施时将增加明确的 Codex Skill 根目录解析，并同步文档；避免同时安装两份造成触发歧义。

## 风险与边界

- 内容与排版包含主观判断，因此脚本只验证结构和可测约束，语义质量仍需证据账本和人工视觉审阅。
- 飞书 API 能验证块树与画板节点，不能替代最终页面视觉检查。
- 删除或替换飞书块属于有损操作，必须继承 `kala-feishu` 的删除确认规则。
- Skill 不保存 OAuth 凭证或会议敏感内容；运行期纪要包留在项目或用户文档目录。
