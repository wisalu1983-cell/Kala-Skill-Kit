# Completion & Verification Claims

## 声明当前状态必须有当前完整证据

ALWAYS 在声明“测试通过”“QA 完成”“全量通过”“版本已完成”“可收口”或“可验收”等当前状态前，先确认真实验证入口、当前执行结果和声明覆盖范围都已验证。

NEVER 用旧测试结果、文档中的“已完成”或“build ✓”、缺失的脚本入口、局部自动化结果或自动化子集代替当前完整证据。

ALWAYS 如果只完成了局部验证，明确标注验证范围和未执行项；例如“单测通过但构建未验证”“自动化通过但第三层 QA 未跑”“功能完成但整版全量 QA 未完成”。

## 完成 = 流程步骤全走完 + 项目级约束满足

ALWAYS 在执行任何流程（外部 skill、项目文档路由、evolve 捕获、代码实现等）时，区分两层要求并同时满足：

1. **流程自身的步骤**：流程定义的每一步是否都已执行（不跳步）
2. **项目级约束**：产出是否满足项目 CLAUDE.md / PM 写入规则 / Specs 索引规则等独立于流程的不变量

两者必须同时满足才算完成。流程告诉你"怎么做"，项目约束告诉你"做完后世界应该处于什么状态"。只检查前者不检查后者，就会反复出现"流程走完了但项目状态不一致"的问题。

NEVER 因为"流程说做完了"就跳过项目约束检查。
NEVER 因为"产出物已经写了"就跳过回读验证内容是否匹配意图。
