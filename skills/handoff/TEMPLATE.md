# Handoff 文档模板

写文件时严格照下面 8 段。段名不要改——`resume` 和下一个 agent 靠这些固定段名定位信息。
用与对话相同的语言书写。某段确实没有内容就写「无」,不要删段。

```markdown
---
title: {一句话概括这次交接的工作}
date: {YYYY-MM-DD HH:mm}
status: {进行中 | 已完成 | 受阻}
chain: {话题标签,例如 landing-redesign-a1b2}
seq: {这是本话题第几棒,从 1 开始}
parent: {上一棒的文件名,或 none —— 本话题第一棒}
related: {同目录下其它并行但无关的 handoff 文件名,逗号分隔;无则 none}
---

## 1. 背景与目标
{3-5 句。这件事为什么存在、要解决什么、你期望到达的最终状态。
让一个完全没参与过的人读完就懂「我们在干嘛、为什么」。}

## 2. 当前状态
{10-20 条要点:现在做到哪了、产出物分别在哪些文件、哪些成了哪些没成。
少于 8 条通常是挖得不够。带上具体文件路径和真实数字,不要只说「优化了」——说「从 X 改成了 Y」。}

## 3. 过程记录(按时间线)
{每一个试过的方向:想法 → 做了什么 → 结果如何。
**尤其是被放弃的方案,以及放弃的原因**——这是重来最贵、最容易丢的信息。5-15 条。
包含上一棒(若有)延续下来的关键过程,别让链断掉。}

## 4. 关键决策
{每一个非显而易见的拍板:选了什么、为什么、否掉了哪些备选。5-10 条。}

## 5. 用户反馈(尽量引用原话)
{用户给过的每一条方向性意见:纠正、偏好、不满、新需求、流程要求。
用引用体保留原话,不要转述成你的理解——这是校准下一个 agent 判断的依据。}

## 6. 下一步
{有序列表。第一条必须是「接手后要做的第一件事」。3-7 条,带优先级。}

## 7. 待解问题
{还没想清、需要进一步确认或调研的点。1-5 条;没有就写「无」。}

## 8. 快速上手
{给下一个 agent 的最短路径:
- 先读哪 2-4 个文件(最重要的)
- 相关数据/产出物在哪
- 若本话题有前序 handoff,列出链条:file1 → file2 → 本文件
- 接手第一步该验证什么}
```

---

## 写完必过的自检(6 项,逐条打勾,缺哪项就回去补哪段)

- [ ] **背景**:没参与过的人能看懂「在干嘛、为什么」吗?(第 1 段)
- [ ] **过程**:试过并放弃的方案、以及原因,写清了吗?(第 3 段——最容易漏)
- [ ] **现状**:产出物具体在哪些文件、做到哪一步,有没有含糊?(第 2 段)
- [ ] **决策**:每个拍板都带了「为什么」和被否的备选吗?(第 4 段)
- [ ] **用户反馈**:是原话引用,还是被你转述改写了?(第 5 段)
- [ ] **下一步**:第一条是不是明确到「接手就能动手」?(第 6 段)

任一项不过关,先把对应段补厚再收尾。
