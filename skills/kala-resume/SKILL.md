# 恢复交接 (Resume)

用户刚换到这台设备/这个 agent,要接手之前的工作。

## 步骤 1:同步 + 定位

```bash
ROOT=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
git -C "$ROOT" pull -q 2>/dev/null   # 有远程才拉,失败不阻塞
date "+%Y-%m-%d %H:%M:%S %Z"          # 真实时间,用于判断「几天前」等
ls -t "$ROOT/.handoff/"/HANDOFF_*.md 2>/dev/null   # 按修改时间倒序
```
若 `.handoff/` 不存在或为空:告知「本项目还没有交接文档,可能上一台设备没跑 `/kala-handoff`」,结束。

## 步骤 2:选定要接哪条——不默认「最新那条就是」

- **用户在 `$ARGUMENTS` 里指定了话题/文件名** → 直接读匹配的那份。
- **没指定** → 读每份文件的 frontmatter(`title/chain/seq/date/status`),**按 chain 分组**,每组只列最新一棒,呈现给用户,例如:
  ```
  发现 2 条交接线:
  1. [landing-redesign-a1b2] seq 3 · 进行中 · 07-19 · 落地页改版
  2. [pricing-copy-9f3c]     seq 1 · 受阻   · 07-18 · 定价文案
  你要接哪一条?
  ```
  让用户选,**不要自作主张认定最新的那条**——并发下可能有多条互不相关的活。

## 步骤 3:读全链

读选定的文件。若它 `parent` 不是 none,**顺着 parent 往上把本链前序也读了**(至少读到能看懂来龙去脉),这样过程和决策不断档。`related` 里的文件是旁支参考,按需读,不当作续接。

## 步骤 4:复述理解,等确认

按交接文档,向用户复述你接收到的五类信息,证明无损接手:
1. 背景与目标
2. 当前状态(产出物在哪、做到哪)
3. 试过什么、放弃过什么(及原因)
4. 关键决策
5. 下一步第一件事

对文档里标了 `[?]` 的存疑点,主动指出「这条上一棒也不确定,我先核实」。
然后**等用户确认或纠偏后再动手**,不要读完就直接开干。

## 只读原则

本流程**绝不**修改、清空、删除任何交接文档。交接记录是历史,保留。接手后的新进展,由用户下次显式跑 `/kala-handoff` 另写新一棒。
