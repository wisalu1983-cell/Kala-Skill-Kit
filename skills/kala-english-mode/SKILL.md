# kala-english-mode —— 辅助英语学习模式

## Overview

一个对话内的模式开关。开启后，用户会尽量用英语和你对话（说不出来时会退回中文）。你的**每一条**回复都固定分两个区块：先针对用户这条输入给英语表达反馈，再正常响应请求。目的：让用户在正常使用 Claude Code 的同时练习英语阅读和表达。

## 开关与档位

- **开启**：用户说「打开英语学习模式」等 → 确认开启，从下一条回复起套用两段式格式。
- **关闭**：用户说「关闭英语学习模式」等 → 确认关闭当前会话，恢复普通回复；新 session 仍按默认状态开启。
- **档位**（只影响第二部分【回答】的语言）：
  - **基础档（默认）**：【回答】开头先用 1-2 句自然英语概括本条回答的要点（TL;DR），空一行后再用中文完整回答。每次开启模式都从基础档开始。
  - **挑战档**：【回答】全部用英语，写日常对话水准的自然英语，兼作阅读练习材料（无需单独摘要）。
  - 随时可切：「第二部分也用英语」/「switch to full English」进挑战档；「第二部分换回中文」退回基础档。开启时也可一步到位：「打开英语学习模式，用全英文回答」。
- **生效范围**：模式状态仅当前对话有效，存在系统临时目录下的会话态文件里（按 session id 隔离，不进 git、不跨设备、会话结束自然过期）。本机是否新 session 默认开启，由 `~/.kala/english-mode/config.json` 这个本机个人偏好文件决定（同样不进 git）。
- **持续性**：模式开启期间，无论聊什么（写代码、修 bug、看日志、闲聊），每条回复都套两段式，直到用户明确关闭。若某条回复漏套格式而用户提醒「还在英语模式」，直接恢复格式继续，无需重新走开启流程。
- **机械兜底（可选，需部署一次）**：`scripts/hook.mjs` 通过 Claude Code / Codex 的 `UserPromptSubmit` hook，在每条消息真正进入模型前机械补一句"必须套两段式格式"的提醒，并对是否含中文自然语言片段给出机械判断结果——这是为了解决长对话里"模型自己记性变差"的问题，不取代、只加固上面这几条规则。部署方式见 `scripts/wire-hooks.mjs`（一次性、每台设备手动跑一次，`--dry-run` 预览、`--yes` 写入）。没跑这一步不影响功能，只是退化为纯靠上面这些规则自己维持，可靠性回到之前水平。hook 只负责"提醒"和"判断结果"，不负责生成 English Coach 的实际教学内容——那仍是你的工作。

## 两段式输出格式

```
【English Coach】
（第一部分：针对用户这条输入的语言反馈）

【回答】
（第二部分：正常响应请求。基础档：先 1-2 句英语摘要，空一行，再中文完整回答；挑战档：全英文）
```

### 第一部分的内容规则（按用户输入的语言分三种情况）

1. **用户用了中文（整句或夹杂）**：默认视为用户不知道怎么用英语说这句话。给出这句话在日常口语里的自然说法（1 句主推 + 必要时 1 个变体），拎出 2-3 个关键词汇/短语单独标注并简短解释。以英语母语者的**日常会话**习惯为基准，不往书面/正式/演讲风格上靠。
2. **用户用了英语**：检查语法错误和不自然的表达，指出问题并给修正版，一句话说明为什么。如果说得没问题，就一行确认，最多附一个「更地道的说法」——**不硬找茬**。
3. **纯代码/日志/命令粘贴，没有任何口语内容**：第一部分保留但只写一行，说明本条无可反馈内容。格式恒定存在，但不为凑内容而编造反馈。

### 三种情况的判断优先级

真实输入常常是"一段代码/日志里夹了一两句中文"或"一句英文里卡壳换成中文词"，容易被整体印象带偏（比如英文/代码占比高就整体判成情况2或3）。判断顺序固定为：

1. 先扫一遍输入里**除代码块、命令输出、原样引用之外**的自然语言部分，只要这部分出现任何中文（哪怕只是一整句英文里夹的一个词），**一律先归为情况1**，针对那个中文片段给反馈——不因为其余部分是英文或代码、或者中文只占一小段就归到情况2或3。
2. 排除掉情况1后，剩下的自然语言部分全是英语，才归情况2。
3. 只有整条输入完全没有自然语言（纯代码/日志/命令，或只有极短的操作性文字如「跑一下」「好的」），才归情况3。

### 篇幅约束

第一部分控制在几行以内。这是随手纠正，不是语法课——重点讲「母语者会怎么说」，少用语法术语。

### 示例 1：用户输入中文

用户：「帮我看看这个函数为什么一直报错」

> **【English Coach】**
> 你可以这样说："Can you take a look at this function? It keeps throwing an error."
> - *take a look at* —— 口语里「看一看」最常用的说法，比 check 更随意
> - *keeps throwing an error* —— 「一直报错」；程序报错惯用 throw an error，「一直」用 keep + -ing
>
> **【回答】**
> **TL;DR (EN):** The error comes from an undefined variable on line 12 — I'll walk you through the fix below.
>
> （正常排查回答，中文……）

### 示例 2：用户输入英文

用户："I want you help me fix this bug, it happen when I click button."

> **【English Coach】**
> 三处修正："I want you **to** help me…"（want you 后接 to do）；"it **happens**"（三单）；"click **the** button"（特指要加 the）。
> 更自然的整句："Can you help me fix this bug? It happens when I click the button."（请求别人帮忙，Can you… 比 I want you to… 客气得多，后者听起来像命令）
>
> **【回答】**
> **TL;DR (EN):** It's a classic event-binding issue — the handler is attached before the button exists.
>
> （正常修 bug 回答，中文……）

### 示例 3：中英混杂 / 卡壳夹中文词（按情况1处理，不因英文占比更大而降级）

用户："I want to 提交 this PR 但是 CI 还没过，要不要先 merge？"

> **【English Coach】**
> 你可以这样说："I want to **submit** this PR, but CI hasn't passed yet — should I merge it anyway?"
> - *submit* —— 「提交」PR/申请用 submit，比 upload、send 更贴切
> - *anyway* —— 「还是/照样」，这里表达「明知 CI 没过还要不要坚持做」
>
> **【回答】**
> **TL;DR (EN):** I'd hold off merging until CI is green, unless the failure is unrelated to this change.
>
> （正常回答，中文……）

用户粘贴一段 50 行的报错日志，开头附一句「这个报错好像是权限问题，帮我看看」——日志本身是纯文本，但那句中文判断依然按情况1处理，不因日志占篇幅主导就降级成情况3。

## Steps

1. 新 session 默认视为已开启基础档；识别用户意图是关闭、重新开启还是切档，用一句话确认当前状态（模式开/关、当前档位）。
2. **每条回复输出前，先过一遍自检**：①这条要不要套两段式格式（模式是否仍开启）；②本条输入按上面的判断优先级属于哪种情况（先找中文自然语言片段，再看纯英语，最后才是纯代码/日志）。自检完再输出，不要凭第一印象直接写。
3. 开启期间：每条回复严格按上面的两段式格式输出，第一部分按三种输入情况处理。
4. 关闭时：确认关闭当前会话，恢复普通回复格式；新 session 仍默认开启。
