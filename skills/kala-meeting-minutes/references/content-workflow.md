# 内容提炼工作流

## 目的

把长转录压缩成可靠纪要，同时保留足够证据让协作者判断“这是会议结论，还是模型总结”。

## 一、先标准化输入

### 说话人表

在处理正文前建立映射：

| 转录标签 | 真实姓名/角色 | 可信度 | 依据 |
|---|---|---|---|
| 说话人 1 | 已确认姓名 | 已确认 | 用户提供 |
| 说话人 2 | 待确认 | 未确认 | 转录标签 |

不要在不同章节交替使用“说话人 1”“主持人”和真实姓名。用户没有确认姓名时保留原标签。

### 术语表

记录项目名、系统名、角色名、缩写和用户要求替换的命名。遇到同音词或转写错误，先查上下文和样例；无法确认就保留原词并标注疑点。

### 范围表

至少记录：当前阶段、时间窗口、明确重点、明确不展开项、会议目标、用户后来补充的约束。

## 二、按议题切分，不按固定分钟切分

先顺序读完整转录，再以议题转折、决策点、任务分派和阶段变化切分。每个片段记录：

```json
{
  "start": "00:00",
  "end": "05:32",
  "topic": "首版范围",
  "speakers": ["说话人甲", "说话人乙"],
  "summary": "讨论并确认首版只覆盖核心流程"
}
```

固定每五分钟切段会把一个结论拆散，也会把两个不同议题混在一起。

## 三、建立证据账本

建议结构：

```json
{
  "id": "decision-01",
  "kind": "decision",
  "summary": "首版只覆盖核心流程",
  "status": "confirmed",
  "scope": "当前阶段",
  "evidence": [
    {
      "timestamp": "04:10",
      "speaker": "说话人甲",
      "quote": "首版先把核心流程跑通"
    }
  ]
}
```

`kind` 推荐值：

| 类型 | 含义 | 是否进入关键结论 |
|---|---|---|
| `fact` | 已知背景或现状 | 视重要性 |
| `opinion` | 个人判断或偏好 | 通常不直接进入 |
| `decision` | 会议已经拍板 | 是 |
| `direction` | 明确方向，但实现仍待定 | 可进入，注明边界 |
| `candidate` | 候选方案 | 进入开放问题，不写成结论 |
| `action_item` | 明确需要执行的动作 | 进入待办 |
| `open_question` | 仍需核实或决策 | 进入待确认 |
| `future_scope` | 后续阶段内容 | 只保留必要边界 |
| `quote_candidate` | 可能成为金句的原话 | 经核对后使用 |

`status` 至少区分 `confirmed`、`leaning`、`unconfirmed`。未确认项必须写 `unresolved_reason`。

## 四、判断什么值得进入总结

一个内容满足下列任一条件时优先保留：

- 会改变产品目标、技术路径或工作范围；
- 是明确决策、否决或边界；
- 形成具体待办、负责人、期限或依赖；
- 解释多个讨论点之间的核心关系；
- 是后续协作者容易误解的重要定义；
- 用户明确要求记录。

重复讨论、表达性铺垫、无结论争论和与当前范围无关的未来细节可以压缩。

## 五、从证据账本生成栏目

### 总结

用一段话回答：为什么开会、确认了什么、当前重点是什么、还有哪些关键未决项。避免把所有待办逐条复述一遍。

### 关键结论

按因果或层级组织，不按发言顺序罗列。每条包含结论本身及必要边界。复杂关系优先转为视觉图，不用长段落替代结构。

### 待办

推荐格式：

```text
[负责人/待确认] 动作；期限；依赖；验收结果。
```

转录没有给出的字段写“待确认”。不要根据职位替会议指定负责人。

### 智能章节

按议题顺序呈现，标题包含开始时间和议题。正文概括讨论结论与必要上下文，不复述全文。

### 金句

必须来自原文并核对说话人。优先选择能够界定目标、原则或取舍的短句；口误或依赖大量上下文的句子不适合作为金句。

### 完整转录

保留原始顺序、时间戳和说话人映射。只做明确的转写纠错，不把摘要反写进原文。

## 六、样例反推清单

比较样例成品与其完整转录时，记录：

- 总结覆盖了哪些议题、压缩到何种粒度；
- 哪些内容被提升为关键结论；
- 待办如何写负责人和期限；
- 智能章节的平均跨度和标题风格；
- 金句如何选择；
- 图、画板、引用、列表和留白如何组合；
- 完整转录位于哪里，是否折叠或分段。

输出一份“方法规格”，再用它处理新会议。不要复制样例句子作为占位内容。

## 七、用户纠正后的传播更新

用户纠正说话人、术语、范围或日期时：

1. 更新约束表；
2. 搜索纪要正文、证据账本、视觉图、发布计划和完整转录中的全部出现位置；
3. 判断哪些结论因纠正而改变；
4. 重新运行内容 QA；
5. 报告受影响范围。

只改用户点名的一句会让同一文档出现互相矛盾的版本。
