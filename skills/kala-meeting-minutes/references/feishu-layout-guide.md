# 飞书纪要排版与发布指南

## 目标

让纪要既符合飞书妙记式阅读节奏，也能在修改现有文档时准确落到用户指定位置。内容结构和视觉结构分别设计、分别验收。

## 一、发布前先确认四件事

1. 目标 URL 属于哪个租户和账号；
2. 当前操作是新建、全量重写、原位替换还是追加；
3. 目标文档已有块的顺序、父子关系、块类型和资产 token；
4. 哪些内容必须保留，哪些删除需要用户确认。

输入或输出涉及飞书时使用 `kala-feishu`。传完整 URL让其自动路由账号；只有 token、folder token 或 space id 时显式指定账号，不能凭默认账号猜。

## 二、妙记式信息层级

典型阅读顺序：

```text
会议元信息
AI 提示
总结
关键结论 / 关键视觉
待办
智能章节
关键决策
金句时刻
相关链接
完整转录
```

具体栏目以样例和用户要求为准。核心原则是先给结论与行动，再给讨论过程和原始证据。

## 三、视觉媒介选择

| 信息类型 | 推荐媒介 | 不适合的情况 |
|---|---|---|
| 3–6 条并列重点、时间阶段、范围总览 | 飞书原生画板或卡片 | 用户已指定保留图片/SVG |
| 复杂系统架构、反馈回路、多向关系 | SVG/高分辨率图片 | 原生画板无法稳定表达箭头或布局 |
| 原始白板作为会议证据 | 原图 | 用户要求用整理后的结论替换其位置 |
| 简单顺序流程 | 原生画板 | 字太多、节点过密 |
| 需要复制搜索的详细说明 | 文档正文 | 不要把整段正文塞进图 |

视觉媒介一经用户确认就锁定。想从 SVG 改成原生画板、从原图改成重绘图，必须先说明影响并得到确认。

## 四、飞书原生画板标准

### 画布与布局

- 默认采用横向阅读或清晰的上到下流程，不混用多个主方向；
- 主内容在一个视口内可理解，避免无意义的大画布；
- 卡片间距一致，边距明显，底部区域不能被压扁；
- 信息分为标题、核心结论、主体卡片和必要注释四个层级；
- 背景、边框和强调色服务于分组，不为每个框随机换色。

### 字体

- 画板标题建议 24–32 px；
- 分区标题建议 20–24 px；
- 卡片标题建议 18–22 px；
- 正文建议不低于 16 px；
- 注释建议不低于 14 px。

实际可读性优先于固定数值。导出预览后若正常缩放下需要放大才能读，判定失败。

### 文本容量

- 一张卡片只表达一个主题；
- 正文超过 4–6 行时优先拆卡片或移到文档正文；
- 先给文字留空间，再画背景框；
- 中文、英文、数字混排需保留额外宽度；
- 创建节点后必须导出图片检查超框和遮挡。

### 关系与箭头

箭头、连线、虚实线和回路属于语义：

- 单向箭头表示输入、调用、依赖或结果流；
- 双向关系表示互动或互相影响；
- 回路表示结果反馈到前序状态；
- 虚线用于待验证、异步或旁路，含义必须有图例；
- 无法使用原生箭头时，使用可读的箭头符号、分段线或改用 SVG，不能直接删除关系。

## 五、SVG 与图片标准

- 优先保留矢量源，并输出宽度足够的 PNG 作为不支持 SVG 时的显示资产；
- 建议画布宽度至少 1400 px，文字在文档默认宽度下仍可阅读；
- 保持原始宽高比，不拉伸；
- 图内标题与文档标题避免重复占据大量空间；
- 所有箭头端点、框线和文字必须完整；
- 图中被删除或弱化的白板内容应在旁注中说明，不能悄悄丢失。

## 六、精确位置替换流程

### 读取

获取文档全部块，筛出顶层块并按索引列出：标题文本、块类型、block id、image token、board token。必要时同时读取子块。

### 建立操作表

```text
目标 1：顶层索引 4，原图片块 A
动作：替换为原生摘要画板
保留：前一标题、后一正文

目标 2：顶层索引 5，原图片块 B
动作：替换为 visuals/architecture.svg 的显示图
保留：原始宽高比
```

### 确认

把所有会删除的块列给用户。用户确认后再执行。确认只覆盖列出的对象；后续发现额外目标时需要再次确认。

### 执行

- 优先先创建并验证新内容，再删除旧块；
- 若 API 不支持移动，读取原内容并在目标索引重建；
- 删除多个块时每次重新读取或动态计算索引，避免前一次删除导致后续索引偏移；
- 非幂等请求失败时先回读现状，不直接重跑；
- 不用“先追加、以后再整理”代替原位替换。

### 回读

确认：

- 新块紧邻预期标题和正文；
- 旧块 token 不再存在；
- 文末没有重复标题或重复视觉；
- 画板节点数量、图片尺寸和媒介类型正确；
- 其他正文块 ID/内容未被误改。

## 七、实际渲染验收

API 回读只能证明结构，不证明视觉。至少查看：

- 桌面端默认缩放下的整图；
- 文字是否超框、遮挡、过小；
- 卡片是否拥挤，底部是否被压缩；
- 箭头是否清晰连接正确对象；
- 图与后续正文之间是否有合理留白；
- 标题层级是否与样例一致。

发现问题时先判断是内容容量、布局尺寸、媒介选择还是位置错误，再做局部修复。

## 八、常见失败模式

| 失败 | 原因 | 修复 |
|---|---|---|
| 新内容出现在文末 | 未识别原始目标块 | 读取块树，按索引原位替换 |
| 同时保留旧图和新图 | 把替换当追加 | 删除前列清单并确认 |
| 图中文字都在但不好读 | 只验节点/文本，不验渲染 | 导出预览并检查字号、超框、留白 |
| 为了整齐删箭头 | 把关系当装饰 | 恢复关系或改用 SVG |
| 原生画板与样例不像 | 只复制内容分区 | 同时匹配层级、密度、间距和文本样式 |
| 写入错误租户 | token 缺少域名路由信息 | 传完整 URL或显式指定账号 |
