# 无 Skill 基线观察

基线来自 2026-08-05 至 2026-08-06 的真实会议纪要制作过程。当时尚无 `kala-meeting-minutes`，因此可直接观察模型在内容提炼、视觉选择和飞书发布上的自然失误。受当前会话禁止子代理约束，不额外生成模拟基线。

## 场景一：已有飞书纪要中的两张白板需要替换

期望：第一张原始白板所在位置替换为原生摘要画板，第二张原始白板所在位置替换为 SVG 架构图。

实际基线：先保留了两张原图，又把新内容追加到文末；后续虽然把第二张原生画板换成 SVG 图，仍未理解“原始白板的位置”是目标锚点。用户再次明确后才删除原图并把两项内容移到正确位置。

暴露的问题：

- 未在写入前读取并编号目标文档块树；
- 把“替换内容”误解为“在文档里增加新版内容”；
- 只验证内容是否存在，没有验证位置和重复块；
- 删除/替换计划没有在执行前用自然语言列清楚。

## 场景二：专业架构图改为飞书原生画板

期望：关系清晰、字号可读、卡片不超框；用户最终要求保留原 SVG 方案。

实际基线：原生画板先出现字号偏小、文字超框、卡片拥挤和底部压扁；为整理版面移除箭头后，内容块之间的逻辑关系明显变弱。随后才恢复关系指示。用户最后决定第一张使用原生画板、第二张保留 SVG。

暴露的问题：

- 把“文字都放进图里”当作视觉质量合格；
- 把箭头视为装饰，而非架构结论的一部分；
- 没有在绘制前锁定视觉媒介；
- 只检查节点数量，未优先检查真实渲染的字号、超框、留白和关系。

## 场景三：从转录提炼关键结论

期望：聚焦当月工作，正确映射说话人和术语，保留关键架构分工，未定内容不展开。

实际基线：关键结论“LLM 决定做什么和目标，GOAP 规划实现路径”需要用户提醒后补入；“主持人”命名有歧义，后改为“NPC上下文编排器”；“无边界的自由生成”表述无法让协作者理解；月份范围和说话人映射也依赖用户逐次纠正。

暴露的问题：

- 没有先建立术语表、说话人表和范围约束；
- 没有区分已确认结论、候选实现和未来讨论；
- 摘要压缩时遗漏了对实现有决定意义的架构分工；
- 未对抽象术语执行“协作者能否直接理解”的可读性检查。

## 基线结论

无 Skill 时，模型能逐步修正并产出可用结果，但依赖多轮用户纠偏。新 Skill 必须把“证据账本、范围锁定、媒介锁定、位置计划、双重 QA 和发布后回读”前置为标准步骤。
